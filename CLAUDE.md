# Riichi Night: notes for Claude

Offline riichi mahjong for Android: the player against three anime heroines.
React 18 + TypeScript + Vite UI, the pyriichi rules engine in Pyodide inside a
Web Worker, Capacitor 6 for the APK, GitHub Actions for builds. Repo:
`bogdanpetrenko13/RiichiNight`, app id `com.bogdanpetrenko.riichinight`.
The owner writes in Russian; reply in Russian.

## Hard rules

- No explicit or sexual content.
- Every character is an adult and must look like one (art, text, ages).
- Never commit art sources (PSDs, model weights, raw ComfyUI renders); only the
  finished images in `public/characters/`.
- `signing/debug.keystore` is a debug key with the public `android` passwords,
  committed on purpose so every CI build updates in place. Never use it for
  release builds.
- Commit messages end with the attribution lines the session gives you.

## Mortal (strong heroines)

The app is AGPL-3.0-or-later because it includes Mortal (`LICENSE`,
`NOTICE.md`). Weights: Mortal S42.8k (Apache-2.0) as float16, release
**mortal-s42**, sha256 in `public/mortal/s42.f16.sha256`; not in git.
`scripts/mortal/ci_setup.sh wasm|native` builds the crate and fetches the
weights (CI does both). The **Mortal kit** workflow publishes what this
container cannot download (crates.io, Hugging Face and PyPI are blocked):
release `mortal-kit` with vendored crates (`mortal-src.tar.gz`), the wasm32
std (`rustlib-wasm32.tar.gz`, unpack into
`~/.rustup/toolchains/stable-x86_64-unknown-linux-gnu/lib/rustlib/`), the
weights and PyTorch reference data. Local build offline:

```bash
# cargo-offline.toml: [source.crates-io] replace-with = "vendored-sources",
# [source.vendored-sources] directory = "<kit>/Mortal/vendor", [net] offline = true
cd native/mortal
cargo build --release --lib --config cargo-offline.toml           # for CPython tests
RUSTFLAGS="-C target-feature=+simd128" cargo build --release \
  --target wasm32-unknown-unknown --config cargo-offline.toml   # for the app
cargo run --release --example check_net --config cargo-offline.toml -- s42.json s42.bin <ref>   # vs PyTorch
```

Rules against Mortal: `MORTAL_LIB=native/mortal/target/release/libriichinight_mortal.so
MORTAL_DIR=public/mortal python tests/python/mortal_selfplay.py 4 1` plays
four Mortal seats and prints every disagreement between pyriichi and libriichi
(legal actions, discardable tiles, points of each win). Keep it at zero;
`tests/python/test_mortal.py` checks it in CI. Tenhou game records may not be
used (their terms forbid it for apps that don't need Tenhou).

If the npm or PyPI registry is unreachable:

- Run test files without pytest by importing them and calling every `test_*`
  function.
- Build a preview with `scripts/preview/build.sh`. It needs an esbuild binary
  (`ESBUILD=`), the Pyodide files (`PYODIDE_DIR=`) and React reachable via
  `NODE_PATH`. Then point `E2E_DIST` at `.preview`.

Dependencies: CI installs exactly what `package-lock.json` pins (`npm ci`).
After changing `package.json`, run the **Refresh package-lock.json** workflow
(`gh api -X POST repos/bogdanpetrenko13/RiichiNight/actions/workflows/lockfile.yml/dispatches -f ref=main`),
then `git pull` the commit it pushes; Claude's container cannot reach npm.

Engine errors reach the player as `ErrorDialog` (retry / continue from the
last save / title) with a copyable report; e2e injects a failure by serving a
patched `bridge.py` (`_inject_engine_failures`).

CI (`.github/workflows/android.yml`):

1. Engine tests.
2. Web build.
3. Pyodide smoke test.
4. Browser tests; the screenshots are uploaded as artifact `e2e-screenshots`.
5. The debug APK, signed with the fixed key.

GitHub) makes CI publish `RiichiNight-vX.Y.Z.apk` in that release, with notes
from `docs/releases/vX.Y.Z.md`; the tag must match `package.json`'s version

## Conventions

- Visual changes: check portrait (412×915) and landscape, both table styles
  (`quiet`, `felt`), dark theme.
- Minimum Android System WebView is 105 (`MIN_WEBVIEW` in
  `scripts/check-css-compat.mjs`; CI runs it). Tests run in a current
  Chromium, so a CSS feature newer than that (e.g. `color-mix()`, 111) needs a
  plain declaration of the same property before it, or it silently vanishes
  on emulators and older phones.
- Layout sizes shared by `useLayout.ts` and the CSS live in `src/ui/metrics.ts`
  (set as custom properties on the table root); stacking order only via the
  `--z-*` scale in `tokens.css`, never a raw `z-index` number.
- Text style: weights from `--fw-*` (400 / 600 / 700, 900 only for calls);
  every call announcement (cutaway, rival and player plaques) uses the
  `--call-*` tokens and `--font-call` (bundled Inter Black, `public/fonts`,
  loaded in `src/main.tsx`; heavy capitals); small capital labels use `--caps-ls`.
- Rivals' lines: say them through `maybeSay` (chance × her `chatty` × the
  "Rivals talk" setting); new situations need lines for all 12 heroines.
  Your record against each heroine is `records.v1` (`addMatch` in storage).
- Render errors are caught by `ScreenErrorBoundary` (same recovery dialog as
  engine errors); e2e triggers one with `window.__rnCrash = "table"`.
- Saves pickle the whole `Game` (engine, brains). A new attribute on `Game`,
  `Brain` or anything pickled must be read with `getattr(obj, "name", default)`
  so games saved by older builds keep working (see
  `test_old_save_without_new_attributes_keeps_playing`).
- New engine data shown in the UI: add the type to `protocol.ts`, keep old
  saves working (optional fields), add a Python test that the numbers add up.
- Difficulty ladder: each heroine's `step` (1–12) and `level` in
  `src/game/characters.ts`; steps 1–4 are open, each next one unlocks with a
  1st place in a match with the previous step's heroine. Levels are
  calibrated with the **AI strength** workflow (`strength.yml`, sides
  `"<level>/<style>|mortal"`, 400 east games): average place against three
  Mortal seats runs evenly from ~3.59 (step 1) to ~2.46 (step 12), ~0.1 per
  step. Re-run it after AI or rule changes.
- AI changes: check `python tests/python/style_stats.py 8` (table of calls,
  riichi, win / deal-in rates, safe discards under riichi per style) and keep
  `tests/python/test_styles.py` passing.
- Animations: `tests/e2e/test_motion.py` follows tiles frame by frame
  (`motion_probe.js`): no frame may cover more than ~40 % of a flight, flights
  start at the source tile, the hand must not shift on draw / discard, and
  nothing stays transformed afterwards. Keep it passing when touching
  `motion.ts`, `PlayerHand`, `RivalBand` or `PlayerBand`.
- New game situations worth testing: add a scenario to `scenarios.py` and an
  e2e test instead of waiting for it in random play.
